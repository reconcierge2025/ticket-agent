# סוכן הכרטיסים 🎟️

סוכן שסורק את **קופת תל אביב** (וגם comy / grayclub) ואת **Ticketmaster ישראל**, מוצא את המקומות הכי קרובים לבמה בכל אזור, ושולח לך הודעה בטלגרם.

## מה הוא עושה
- **שולח לו קישור למופע:** הוא בודק **את כל התאריכים** ושולח מיד את **הכי טוב שמצא**, בכל אזור (VIP / רחבה / אולם / יציע) ולכל כמות של **2, 3, 4 ו-5 כרטיסים צמודים**. הוא שולח גם אם הכי טוב רחוק משורה 4, ו-🎯 מסמן שורות 1–4.
- **בכל שעה הוא בודק שוב.** אם נמצא משהו קרוב יותר, תקבל "⬆️ נמצאו מקומות קרובים יותר" עם השורה הקודמת.
- **סריקה כללית:** הוא עובר על כל המופעים באתרים ושולח **הודעת סיכום אחת** עם מה שבשורות 1–4.
- **מצב קנייה (`/sale`, במחשב בלבד):**
  - מחכה בתור ומעדכן אותך ככל שהתור מתקדם.
  - **Ticketmaster:** בוחר לבד את הגוש עם המקומות הכי קרובים, את הכמות, לוחץ "לרכישה" **ומגיע עד עמוד התשלום**. אתה רק משלם.
  - **קופת ת"א:** מפת המושבים באתר היא תמונה ואין בו "בחירה אוטומטית". לכן הסוכן פותח את המופע בחלון שבו אתה מחובר ושולח לך **בדיוק על אילו מושבים ללחוץ**.

> 🔒 הסוכן לא מזין פרטי אשראי, לא עוקף תורים ולא פותר "אני לא רובוט". את התשלום אתה עושה.

## א. בוט טלגרם (פעם אחת)
1. בטלגרם: **@BotFather** ← `/newbot` ← שם ← שם משתמש שנגמר ב-`bot` ← מעתיקים את ה-**token**.
2. פותחים את הבוט החדש ולוחצים **Start**.
3. מספר הצ'אט שלך: כשהסוכן רץ, שלח לו הודעה והוא יחזיר `מספר הצ'אט שלך: ...`.
4. **עוד אנשים:** כל אחד שולח לבוט הודעה, מקבל את המספר שלו ושולח לך. אתה מוסיף את כל המספרים לרשימה, מופרדים בפסיק.

---

## ב. הפעלה בענן – GitHub (בלי מחשב)
1. ב-GitHub: **New repository** ← שם (למשל `ticket-agent`) ← **Create**, **בלי** README.
2. מעלים את הקוד (מהתיקייה של הסוכן):
   ```
   git remote add origin https://github.com/<שם-המשתמש>/ticket-agent.git
   git push -u origin main
   ```
3. בריפו: **Settings ← Secrets and variables ← Actions ← New repository secret**, ומוסיפים שני סודות:
   - `TELEGRAM_BOT_TOKEN`: ה-token מ-BotFather
   - `TELEGRAM_CHAT_IDS`: מספרי הצ'אט, למשל `444349705,123456789`
4. בלשונית **Actions** ← **ticket-agent** ← **Run workflow**, כדי להריץ פעם ראשונה.
5. מעכשיו הסוכן רץ **כל חצי שעה**: עונה להודעות שלך, בודק מופעים שביקשת, ופעם בשעה עושה סבב מלא.
   מה שהוא מצא נשמר בתיקייה `state/` בריפו.

💰 **עלות:** בריפו **ציבורי** GitHub Actions חינם בלי הגבלה. הקוד והסודות מוגנים (הסודות לא נחשפים), אבל רשימת המופעים במעקב בתיקייה `state/` גלויה. בריפו **פרטי** יש 2,000 דקות בחודש בחינם, וזה לא יספיק לסריקה כללית מלאה. במקרה כזה כדאי להשבית את האתרים ב-`sites` (`"enabled": false`) ולעקוב רק אחרי מופעים ששלחת.

⚠️ אתרים לפעמים חוסמים שרתי ענן. אם בענן מגיעות שגיאות ובמחשב לא, זו הסיבה.

## ג. הפעלה במחשב (גם למצב קנייה)
```
npm install
copy config.example.json config.json
```
ממלאים ב-`config.json` את `botToken` ואת `chatIds`. הקובץ הזה **לא עולה לגיטהאב**.

**התחברות לאתרים, פעם אחת** (כדי שבמצב קנייה תהיה כבר מחובר):
```
npm run login -- "https://www.ticketmaster.co.il" "https://tickets.kupat.co.il"
```
מתחברים בחלון שנפתח (גוגל או אימייל) וסוגרים אותו. ההתחברות נשמרת ב-`data/profile`, תיקייה שאסור לשתף.
אם גוגל חוסם ("הדפדפן לא מאובטח"), התחבר עם האימייל והסיסמה של האתר.

**הפעלה:**
- `npm start`: רץ כל הזמן (בוט + בדיקה כל שעה + מצב קנייה).
- הפעלה אוטומטית עם Windows: `powershell -ExecutionPolicy Bypass -File .\install-autostart.ps1`

## פקודות בטלגרם
| שולחים | מה קורה |
|---|---|
| קישור למופע | בדיקה של כל התאריכים, הכי טוב שנמצא ל-2–5 כרטיסים, ואז מעקב |

## הגדרות (`config.json` / `config.example.json`)
- `defaults.quantities`: הכמויות לבדיקה (ברירת מחדל `[2,3,4,5]`).
- `defaults.targetRow`: עד איזו שורה נחשב "יעד" 🎯 (ברירת מחדל 4).
- `defaults.zones`: האזורים ומילים שמזהות אותם. הסדר קובע עדיפות כשיש שוויון בשורה.
- `sites`: אתרים לסריקה כללית. `keywords` מסנן לפי שם, למשל `["שלמה ארצי", "עומר אדם"]`.
- `checkEveryMinutes`: כל כמה זמן סבב מלא.
- `queue.notifyAtPositions`: באיזה מקום בתור לשלוח התראה.

## בדיקות
- `npm test`: בדיקות לוגיקה.
- `node test/e2e.js`: אתר מדומה מקצה לקצה.
- `node test/live.js <קישור>`: קריאה בלבד מהאתר האמיתי. עם `DRY_SELECT=1` גם בודק את הבחירה האוטומטית ב-Ticketmaster, ועוצר לפני "לרכישה".

> כדאי לבדוק את תנאי השימוש של כל אתר לגבי שימוש בכלים אוטומטיים.
